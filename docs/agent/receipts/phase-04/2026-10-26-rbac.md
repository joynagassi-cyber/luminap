## Défaut réel prouvé (audit live, 2026-10-26)

La décision de permission n'existait **que côté TS**
(`rbac.PERMISSION_MATRIX` + `federation.canAccess`). En base :

```sql
SELECT proname FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
 WHERE n.nspname='public' AND p.proname ILIKE '%permission%';
-- → 0 ligne (aucune fonction has_permission)
```

La RLS et le client pouvaient donc **diverger** ; « une décision unique DB↔TS »
était impossible à prouver. Par ailleurs `grants` n'avait **aucun** mécanisme de
refus explicite (pas de `effect`), donc pas de « deny prioritaire ».

**Génération** : `ROLE_PERMISSION_ROWS` est la source ; les `VALUES` SQL en sont
**extraits** (140 lignes), et le test `permissions.test.ts` **relit la migration**
pour prouver l'égalité exacte (anti-dérive) — impossible que DB et TS divergent
sans faire échouer la CI.

## Règles (identiques DB ↔ TS)

1. **Deny** explicite applicable (même portée) → refus (prioritaire).
2. **Rôle canon ACTIF** dans l'org détenant `resource:action` → accord.
3. **Grant allow** actif (non révoqué, non expiré) couvrant la portée → accord.
4. Sinon → refus.

Portées : `scope` absent ⇒ grant **global** exigé ; scope fourni ⇒ couvert par un
élément global **ou** de portée identique. Vocabulaire `resource:action` **libre**
(invariant 9) ; `subject_type='tag'` = sujet de première classe (invariant 10).

## Honnêteté (R12)

- **[Prouvé]** : parité DB↔TS sur 7 cas réels + deny + grant ; 17 tests ; 4 gates.
- **[Limite]** : `has_permission` est livrée **comme primitive** ; les politiques
  RLS existantes n'ont **pas** été réécrites pour l'appeler (elles reposent sur
  `is_org_member`). Réécrire les ~146 politiques serait un chantier à haut risque
  non justifié par un défaut mesuré → **proposition PR18**, pas implémentation.
- **[Non vérifié]** : la sync PowerSync des colonnes `effect`/`expires_at`
  (PowerSync n'est pas déployé ici, E1). Le schéma local est mis à jour en
  cohérence ; la vérification de bout en bout est conditionnée au déploiement.
- **Rôle `ADMIN`** (1 ligne en base, absent du TS `Role`) : reste **hors** du
  modèle canon → refusé par `has_permission`, comme par le TS. Écart de modèle
  connu (cf. JOURNAL session 9), non introduit par cette phase.
