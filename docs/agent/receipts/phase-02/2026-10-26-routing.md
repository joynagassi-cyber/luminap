## Cause racine traitée

La décision « que montrer pour cette URL ? » était **éparpillée** : garde ad-hoc
dans `App.tsx` (`PUBLIC_ROUTES` en dur + `Navigate`), deep link natif dans un
hook séparé, catch-all dans le registre. Trois chemins, trois comportements, et
aucun cas explicite pour « permission manquante », « non-membre », « org du lien
≠ org active », « chunk obsolète » → des cas pouvaient finir sur un écran vide.
Correction (R4/R7) : **un seul résolveur pur** `resolveRoute(url, état)` retournant
un résultat d'un **ensemble fini**, partagé par le web **et** le natif.

## Bugs jumeaux traités (R4)

- **Deep link non-OAuth ignoré** : le hook ne traitait que les callbacks OAuth
  (`if (!code) return`) — un lien `lumina://groups/42` ne faisait **rien**.
  Corrigé : navigation vers le chemin validé.
- **`returnTo` non validé** : aucun contrôle anti-redirection ouverte.
  Corrigé : allowlist interne (`isAllowedReturnTo`).
- **`PUBLIC_ROUTES` en dur** dans `App.tsx` : dupliquait le registre. Supprimé
  au profit du registre unique.
