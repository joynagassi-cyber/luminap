# Forms V2 — Édition, soumetteur réel, dispatch group/account, REJECTED, tableau de données consultables & exportables

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Compléter le système de formulaires dynamiques de Lumina : édition d'un formulaire DRAFT, tracking du soumetteur réel, dispatch des soumissions vers `group` et `account`, statuts REJECTED avec raison, et une vue **tableau de données** des soumissions (consultable, filtrable, exportable CSV/Excel) qui remplace la liste à cartes.

**Architecture:**
- Les types (`src/types/index.ts`) étendent `FormSubmission` (`rejectedBy`, `rejectionReason`) et `FormDefinition` (`targetEntityType` reste un string libre, le dispatcher devient exhaustif).
- `src/lib/formSystem.ts` devient le module central : dispatcher `dispatchFormSubmission()` réutilisable, helpers de format d'affichage des valeurs (`formatSubmissionValue`), et export multi-format (CSV via `buildSubmissionsCSV` existant + XLSX via `xlsx` déjà en dépendance).
- `src/pages/FormSubmissions.tsx` passe de cartes à un vrai tableau (colonnes = champs du formulaire + métadonnées), avec tri, filtre par statut, recherche plein-texte et export CSV/Excel.
- `src/pages/FormBuilder.tsx` gagne l'édition DRAFT (modal réutilisé en mode "éditer") — un formulaire PUBLISHED n'est pas modifiable en place (YAGNI : le versioning complet n'est pas dans ce plan).

**Tech Stack:** React 18 + Ionic React, TypeScript, PowerSync (SQLite local), vitest + @testing-library/react, `xlsx` (déjà dans package.json), `@tanstack/react-table` **ne pas** ajouter — le tableau est simple (colonnes fixes), un `<table>` CSS suffit.

Règles de projet : TDD (test d'abord), commits fréquents, DRY/YAGNI, français pour les libellés UI, conventions des plans existants dans `docs/plans/` (voir `2026-09-22-lot-F-formulaires-rapports.md` pour le contexte du lot F).

**Step 2: Implémenter `dispatchFormSubmission` dans `src/lib/formSystem.ts`**

```ts
import { createGroupPS } from "./dataLayer"; // ajouter au import existant de dataLayer
import { addMemberPS, addEventPS } from "./dataLayer";

/**
 * dispatchFormSubmission — écrit le résultat d'une soumission dans l'entité
 * cible du formulaire (si `targetEntityType` est défini et qu'au moins un
 * champ est mappé via `mapsToEntityField`). Échec capturé et loggé (pas
 * bloquant pour l'utilisateur, la soumission reste retraceable dans
 * form_submissions).
 */
export async function dispatchFormSubmission(
  formDef: FormDefinition,
  mapped: Record<string, any>,
  submissionId: string,
): Promise<void> {
  if (!formDef.targetEntityType || Object.keys(mapped).length === 0) return;

  const toSnakeCase = (key: string) =>
    key.replace(/([A-Z])/g, (m) => "_" + m.toLowerCase());
  const snake: Record<string, any> = {};
  for (const [k, v] of Object.entries(mapped)) snake[toSnakeCase(k)] = v;

  const base = { org_id: getOrganizationId(), ...snake, created_from_form_submission_id: submissionId };

  try {
    switch (formDef.targetEntityType) {
      case "member": {
        const p = { ...base, status: "ACTIVE", joined_at: new Date().toISOString(), archived_at: null, archived_by: null, archive_reason: null };
        await addMemberPS(p as any);
        break;
      }
      case "event": {
        const p = { ...base, status: "PLANIFIED", type: "GENERIC", budget: 0, description: "", budget_items: null };
        await addEventPS(p as any);
        break;
      }
      case "group": {
        // createGroupPS cascade : org_units + groups + accounts + caisses
        await createGroupPS({ name: String(snake.name ?? ""), type: "GROUP", description: String(snake.description ?? "") });
        break;
      }
      case "account": {
        // YAGNI : pas de branche dédiée pour "account seul" dans ce plan —
        // l'onglet "Comptable" (form fill) cible "group" (qui cascade l'account).
        console.warn("[formSystem] targetEntityType=account non supporté seul ; utilisez group");
        break;
      }
      default:
        console.warn(`[formSystem] targetEntityType inconnu : ${formDef.targetEntityType}`);
    }
  } catch (e) {
    // Pas bloquant — log uniquement, la soumission reste dans form_submissions.
    console.error("[formSystem] dispatch failed", e);
  }
}
```

> **Note** : vérifier la signature exacte de `addMemberPS` (`Omit<PSMember, "id" | "created_at" | "updated_at">`) pour que le `as any` reste le minimum possible — affiner les types au fil de la tâche si `PSMember`/`PSEvent` sont exportés depuis `dataLayer.ts`.

**Step 2: Implémenter `exportSubmissionsAsXLSX` dans `src/lib/formSystem.ts`**

```ts
import * as XLSX from "xlsx";

/**
 * exportSubmissionsAsXLSX — exporte des soumissions au format .xlsx.
 * Une feuille, une ligne par soumission ; colonnes = métadonnées
 * (Soumetteur, Date, Statut) + champs du FormDefinition (order trié),
 * même ordre que le tableau à l'écran et que le CSV (cohérence).
 */
export function exportSubmissionsAsXLSX(
  rows: FormSubmission[],
  formDef: FormDefinition,
  filename: string,
): void {
  const fields = [...formDef.fields].sort((a, b) => (a.order ?? 0) - (b.order ?? 0));
  const header = ["Soumetteur", "Date", "Statut", ...fields.map((f) => f.label || f.key)];

  const dataRows = rows.map((sub) => {
    const data = sub.data && typeof sub.data === "object" ? sub.data : (safeJsonParse(sub.data));
    return [
      sub.submittedBy,
      sub.submittedAt ? new Date(sub.submittedAt).toLocaleDateString("fr-FR") : "",
      sub.status,
      ...fields.map((f) => data?.[f.key] ?? ""),
    ];
  });

  const aoa = [header, ...dataRows];
  const ws = XLSX.utils.aoa_to_sheet(aoa);
  const wb = XLSX.utils.book_new();
  XLSX.utils.book_append_sheet(wb, ws, "Soumissions");
  XLSX.writeFile(wb, filename);
}
```

> `safeJsonParse` = petit helper local (déjà présent en logique dans `parseFields` de `FormSubmissions.tsx` — le remonter ici ou le réutiliser, DRY).
