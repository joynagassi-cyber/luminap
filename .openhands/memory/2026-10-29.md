# 2026-10-29 — Cause racine de la suite Cypress « cloud » (audience JWT PowerSync)

## Contexte
Agent « infrastructure de test / sync / compte d'organisation ». Objectif du
propriétaire : suite Cypress E2E **entièrement verte**. Déblocage : Cypress
tourne en local (xvfb + `.env.local` + vite :8080). Compte org E2E :
`lumina-org-e2e@lumina.dev` / `E2e-Lumina!1` (org `org-e2e`).

## Verdict
La suite « cloud » **ne peut pas** être verte : cause racine **infrastructure
PowerSync**, hors code applicatif. L'instance Production
`6a9dd96302481fb31b945823` rejette **tout** jeton d'utilisateur Supabase :

```
401 PSYNC_S2105 — Unexpected "aud" claim value: "authenticated"
```

## Preuve (hors navigateur, déterministe 5×/5)
- POST `/sync/stream` **corps valide** (`{"streams":{"subscriptions":[]}}`) +
  jeton réel → `401 PSYNC_S2105` (aud). Le jeton est ES256, JWKS public résolu
  (`kid=e6d0da61-…`). `aud="authenticated"` (imposé par Supabase).
- Corps **invalide** + jeton bidon → `400 FST_ERR_CTP_INVALID_JSON_BODY`
  (le parseur répond avant l'auth → un 400 ne prouve rien sur l'auth).
- Jeton legacy HS256 (`anon`) → `S2101` (kid introuvable) ; sans jeton → `S2106`.

## Cause
`client_auth.additional_audiences: []` (service.yaml ligne 36, config
déployée). Doc PowerSync : « PSYNC_S2105 … Add `authenticated` to your audience
configuration. » Correctif : ajouter `"authenticated"` puis
`powersync deploy service-config`.

## Specs mesurées en local (xvfb, mono-run)
- `local-dashboard.cy.ts` (offline) → **2/2** ✅ (témoin : app saine hors réplique)
- `sessions.cy.ts` → 0/3 ; `members.cy.ts` → 1/3 ; `forms-v2.cy.ts` → 0/1 ;
  `persistence.cy.ts` → 0/1 ; `cross-tenant.cy.ts` → 0/1. Tous : données
  PowerSync jamais répliquées.

## Écarté (hypothèses testées)
Réplication arrêtée (réparée R80) ; mot de passe `postgres` (réplication) ;
`sync-config.yaml` (le rejet est sur l'`aud`, avant tout stream) ; bug de
sélecteur de spec ; code app (`fetchCredentials` envoie le bon jeton).

## Blocage de livraison
`~/.ps-secrets` **absent** de ce conteneur (note mémoire périmée), `gh auth` non
connecté, pas de jeton admin PowerSync → impossible de déployer depuis l'agent.
Livré : patch `docs/agent/patches/powersync-service-audience.patch` + receipt +
escalade E2 mise à jour. `powersync/service.yaml` **non modifié** (interdit).

## Détails utiles / pièges
- Cypress 16 + `testIsolation` efface `localStorage` entre `it()` → le jeton
  Supabase (localStorage) disparaît ; c'est pour ça que les specs s'appuient sur
  `cy.loginOrgAccount()` (re-login réel) et non sur une session persistée.
- Le serveur vite journalise les 401 PowerSync dans `/tmp/vite.log` (utile pour
  diagnostiquer sans Cypress).
- `git checkout -- cypress/downloads/…pdf` : ce fichier suivi apparaît supprimé
  en début de session ; le restaurer avant de commiter.
