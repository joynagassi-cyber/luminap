# 2026-10-27 — Session 10 : R89.b résolu, R110 découvert, sauvegarde hebdo

## R89.b (PowerSync, descente) — RÉSOLU de bout en bout
- **Cause racine réelle** : 4 streams (`group_memberships`, `event_budgets`,
  `budget_lines`, `custom_field_values`) filtraient par **JOIN** sur le parent.
  PowerSync ne peut pas clé la partition sur une colonne absente de la ligne
  synchronisée → **1 bucket par ligne enfant** → 1 requête de paramètre par ligne
  → plafond **1000** franchi (`PSYNC_S2305`). `org-e2e` = 6709 événements.
- **Hypothèse « profiles > 1000 » = FAUSSE** (108 profils seulement).
- **Correctif** : dénormaliser `org_id` sur les 4 tables enfants (colonne +
  backfill + `NOT NULL` + index + triggers BEFORE INSERT/UPDATE recopiant depuis
  le parent + triggers AFTER UPDATE OF org_id propageant), streams en filtre
  direct `WHERE org_id IN (SELECT org_id FROM profiles WHERE id = auth.user_id())`,
  + colonne `org_id` dans `src/lib/powersync/schema.ts`.
- **Preuve** : token réel → AVANT `PSYNC_S2305` 0 ligne ; APRÈS
  `{"connected":true,"hasSynced":true}` puis `events: 6709`, `members: 161`.
  Faible volume (org-1) : `events:1` → non-régression OK.
- Migrations `20261027000001_denormalize_org_id_sync_scope.sql` (+ rollback).
