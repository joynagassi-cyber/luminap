## Phase 8 (isolation & sécurité)
- **R103 (CRITIQUE, corrigé)** : `public.settle_invitation_claim(uuid)` est
  `SECURITY DEFINER` **et** `EXECUTE`-able par `authenticated` en RPC
  (`/rest/v1/rpc/…`). Elle agit sur `resulting_user_id` (**un tiers**) sans
  vérifier l'appelant → tout utilisateur authentifié peut élever un tiers.
  Preuve live : profil `PENDING`/`MEMBRE` → `ADMIN`/`ACTIVE`, claim `CONFIRMED`.
  Correctif `20261026000005` : garde `pg_trigger_depth()=0` + `REVOKE EXECUTE`
  (settle + toutes les fonctions `RETURNS trigger`) + wrappers de trigger
  re-basculés `SECURITY DEFINER` (sinon le flux légitime casse : `42501`).
  - **Piège appris** : révoquer `EXECUTE` sur une fonction appelée par un
    wrapper `SECURITY INVOKER` casse le wrapper → le repasser en `DEFINER`.
    L'invocation d'une fonction de trigger par le système ne requiert pas
    `EXECUTE`, mais l'appel interne du wrapper, si.
- **Advisors** : ne pas viser 0 sur `authenticated_security_definer_function_executable`.
  Les 7 restants sont des helpers RLS (`is_org_member`, `has_permission`, …)
  appelés dans les policies, prenant l'uid en paramètre : les révoquer casse les
  policies. Seules les fonctions **à effet de bord** doivent être fermées.
- **Entrées hostiles** : les 3 exports CSV (`export.ts`, `formSystem.ts`,
  `ReportBuilder.tsx`) n'échappaient pas les préfixes de formule (`= + - @ TAB CR
  LF`) → injection CSV (OWASP). Correctif : `src/lib/csv.ts`
  (`escapeCsvCell`/`escapeCsvRow`), câblé partout.
