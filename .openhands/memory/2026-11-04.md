## Offline P1/P2 — boot local-first + reprise au retour (2026-11-04, branche fix/offline-session-resilience)
- **CAUSE de la lenteur + déconnexion (prouvée dans la source `@supabase/auth-js@2.114.0`)** :
  `supabase.auth.getSession()` → `_recoverAndRefresh()` fait un **POST /token
  réseau SANS timeout** quand `expires_at` est dépassé (durée de vie access
  token ~1 h = cas NORMAL). `getSession()` était appelé au MONTAGE par
  `RouteGuard` (App.tsx) et `Splash` → le boot **bloquait sur le réseau** avant
  de retomber sur la session persistée (splash long / écran noir). Le refresh
  tourne aussi le refresh token côté serveur : réponse perdue ⇒ token local
  périmé ⇒ `Invalid Refresh Token` ⇒ `handleSessionInvalidated` → **signOut**.
- **P1** : `authService.getSession()` **LOCAL-FIRST** — `readStoredSession()`
  rendu immédiatement ; refresh réseau seulement en arrière-plan borné
  (`SESSION_REFRESH_BOOT_TIMEOUT_MS = 4 s`, `Promise.race`). Sans session
  persistée : attente SDK bornée.
- **P2** : `AppLifecycleBridge` (App.tsx) — `appStateChange` (natif) +
  `visibilitychange` (web) → `authService.resumeSession()` (ne déconnecte
  JAMAIS ; recharge la session persistée ; **n'appelle PAS** le backup
  soft-session pour ne pas ressusciter un compte volontairement quitté) +
  `resumePowerSync()` (reconnecte SEULEMENT si `!connected && !connecting` —
  ne coupe pas une connexion saine, important car `visibilitychange` tire à
  chaque retour d'onglet web).
- **Nettoyage** : `src/lib/offline/` (OfflineService/conflicts) supprimé = code
  mort (aucun import ; le moteur offline réel est PowerSync).
- **Gardes** : `auth-offline-session.test.ts` (+6 cas : local-first sans appel
  SDK, timeout borné, reprise, backup ignoré) ; `offline-resume-guard.test.ts`
  (câblage statique) ; E2E `local-dashboard.cy.ts` (boot hors ligne session
  expirée). Gates : tsc 0 ; vitest **271 fichiers / 2630** ; eslint 0 erreur ;
  build OK.
- **Constat non corrigé (à traiter si l'APK reste cassé offline)** :
  `@powersync/capacitor@0.10.0` **ignore `encryptionKey`** —
  `createConnection(dbFilename, false, 'no-encryption', 1, false)` (TODO du

## Suite (PR #419) — CI verte + durcissement
- **`getSession()` hydrate désormais `state.session`** (sans `profile` ⇒ aucun
  effet de bord) : les consommateurs qui lisent `getState().session`
  (AppContext) voyaient `null` au boot alors que la session persistée existe.
- **E2E `local-dashboard.cy.ts` « session EXPIRÉE » échouait en CI** : le
  refresh du token expiré atteignait le **VRAI** Supabase (l'interception de
  repli `interceptCloud()` ne matche que l'hôte de secours) → rejet
  `invalid_grant` (400) → supabase-js **supprime** la session → `/auth`.
  Reproduit localement (Xvfb + Cypress installés, `CYPRESS_BASE_URL=http://localhost:8080`).
  Correctif : `cy.intercept({method:'POST', url:'**/auth/v1/token**'})` +
  `req.reply({errorCode:'ECONNABORTED'})` ⇒ `AuthRetryableFetchError` = **seul**
  cas où supabase-js PRÉSERVE la session (vrai scénario offline).
  **Leçon** : un test offline doit simuler une PANNE RÉSEAU, pas un rejet auth
  serveur — un rejet auth tue la session à raison.
- **`isOfflineLikeError`** classe désormais **5xx et 429** comme transitoires
  (session préservée) ; un 4xx (invalid_grant) reste invalidant. Évite une
  déconnexion sur simple indisponibilité Supabase.
