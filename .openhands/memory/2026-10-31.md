## R160 — écritures UPSERT sur une VUE PowerSync (« cannot UPSERT a view »)
- **Découverte** : en sondant l'E2E, PR13 (gel de période) et PR8 (maker-checker)
  semblaient inertes. Sonde Cypress : `org_settings` reste VIDE après le clic.
- **Cause racine** : côté client PowerSync expose CHAQUE table comme une VUE
  (`CREATE VIEW org_settings AS SELECT id, json_extract(data,'$.org_id') …`).
  `INSERT … ON CONFLICT (id|org_id,key) DO UPDATE` (et `INSERT OR REPLACE`)
  échoue avec `Error: cannot UPSERT a view` ; `INSERT` sans `id` →
  `Error: id is required`. Preuve : `SELECT name FROM sqlite_master WHERE type='view'`
  → `profiles`, `org_settings`, `organizations`.
- **Correctif** : `setOrgSetting` (src/lib/orgSettings.ts) = `SELECT id` puis
  `UPDATE … WHERE id` OU `INSERT` explicite avec `crypto.randomUUID()`.
- **Leçon clé** : les mocks PowerSync des tests unitaires SIMULAIENT l'upsert en
  JS (`INSERT INTO org_settings` → find/update en mémoire) → le bug était
  invisible en vitest. Le mock lève désormais « cannot UPSERT a view » + garde
  statique `ps-view-upsert-guard.test.ts` (allowlist 2 occurrences latentes).
- **Occurrences latentes** (même classe, consignées E7) : `registerOrg()`
  (capabilities/organization, code mort sans appelant) et `claimInvitation()`
  (capabilities/invitation — + `profiles has no column named status` : le schéma
  PowerSync local omet `status`). Non corrigées : nécessitent une revue de
  schéma/stream PowerSync (divergence client/serveur = PIRE, cf. R80).
- **E2E** : `cypress/e2e/robustness-features.cy.ts` (PR13/PR8/PR15/PR2/PR1) et
  `product-features.cy.ts` (PR12/PR9/PR11/PR16/PR14) — 11 tests verts.
  Non-vacuité vérifiée : revert du correctif ⇒ PR13+PR8 échouent.
- **Piège E2E** : un input contrôlé React (`<input type=date>`) ne se pilote PAS
  avec `.invoke('val')` + `trigger('input')` — il faut le setter natif
  `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el, v)`
  puis `dispatchEvent(new Event('input',{bubbles:true}))`.
- **Piège E2E** : les handlers d'écriture sont `async` fire-and-forget → une
  lecture `__psDb.getAll` immédiate après le clic courtise la course. Utiliser un
  point de synchro UI (statut réaffiché) ou poller.

## Leçon durable : nommage des constantes racines dans cypress/e2e

Les specs `cypress/e2e/*.cy.ts` qui n'ont AUCUN `import` sont des **scripts
globaux** (même portée de programme) : deux `const FOO` racine dans deux
fichiers ⇒ `TS2451` au `tsc -b` du CI. Utiliser des noms uniques par fichier
(préfixe) ou envelopper dans `describe(...)`. Le cache incrémental local
(`tsc -b` sans `--force`) MASQUE l'erreur — toujours `npx tsc -b --force`.
